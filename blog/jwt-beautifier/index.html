JWT Beautifier: Format JSON and Inspect Token Claims

Use a JWT beautifier to make token data readable. Learn what formatting reveals, how to handle errors, and why a JSON decode is not signature verification.

What is a JWT beautifier?

A JWT beautifier is a developer utility that takes the compact token string and presents its parts in a readable form. It typically decodes the Base64url-encoded header and payload, pretty-prints the JSON, and makes claims such as exp or aud easier to inspect.

“Beautifying” and “validating” are different jobs. A beautifier formats data that can be decoded; a validator verifies the signature and applies an expected issuer, audience, time and application policy.

How to use a JWT formatter

  1. Copy the compact token from a controlled development environment. Avoid sharing live production credentials or logging them in a ticket.
  2. Paste the raw value into the JWT inspector. A leading Bearer prefix is common in HTTP authorization headers and may be removed before decoding.
  3. Inspect the header for algorithm and key metadata, then read the payload as JSON.
  4. Review common claims and check whether timestamp values are seconds rather than milliseconds.
  5. Use the output as a debugging clue, not as approval to accept the token.

What should a good beautifier show?

A reliable utility should separate the header, payload and signature segment; preserve JSON types; show malformed inputs clearly; and avoid claiming to verify what it has not checked. Useful quality-of-life features include copying formatted JSON, inspecting standard time claims, accepting a common Bearer prefix and explaining the difference between signed JWS and encrypted JWE compact formats.

It should also state what happens to the input. This implementation decodes locally and does not request a remote decode API, but you should still consider the device and environment where you paste tokens.

Why does my JWT not format?

  • It is not a JWT: an opaque access token may be a random string with no decodable JSON parts.
  • Missing or extra periods: the value may have been truncated or may be an encrypted JWE rather than a three-part JWS.
  • Invalid characters: copy the raw compact token without markup, smart quotes or line decorations.
  • JSON parsing fails: Base64url decoding succeeded but the bytes did not form a JSON object.
  • It decodes but the API rejects it: inspect server-side verification, key rotation, issuer, audience, expiry and application rules.

Security checklist after formatting

After decoding, never assume that sub or role is authentic. Use a maintained library to verify the cryptographic signature with trusted keys and an explicit allowed-algorithm list. Validate claims required by your service, including issuer and audience when applicable, and make authorization decisions from validated context. Keep secrets and private key material out of the token itself and out of screenshots or logs.

The official OWASP JWT guidance is a useful security companion to the JWT specification.

Frequently asked questions

Does a JWT beautifier change the token?

A formatter should only display a readable view of decoded parts; it should not silently modify the original token. Copy the original token separately if you need to preserve it.

Can I format JWT without a secret?

Yes. Decoding the header and payload requires no secret key. The secret or public key is relevant to signature verification, which is a separate operation.

What is the safest way to debug a production JWT?

Prefer a controlled environment and redacted diagnostics. Use trusted tooling and your service’s own verifier; avoid pasting live credentials into third-party tools unless your security policy permits it.

What is the difference between a JWT decoder and a JWT validator?

A decoder reveals the structure and claims. A validator checks a signature and applies expected claim and application policies with trusted configuration.
